How the detector works

  1. Capture — every run fetches the official GameCenter play-by-play and boxscore, and the official Game Summary document, for each game in the window. Each capture stores its URL, HTTP status and retrieval timestamp.
  2. Normalise — all three sources are rendered into one structure: period, clock, team, scorer, assists, strength, own-goal flag and the score after each goal.
  3. Compare — the new capture is diffed against the previously stored capture of the same game. Goals are matched on period + clock + team; anything unmatched is reported as added or removed, never silently re-paired.
  4. Classify — the diff becomes a typed record: goal→no-goal, no-goal→goal, scorer change, assist change, strength change, own-goal annotation change, or non-scoring metadata change.
  5. Assess — the record is flagged as goal-count-affecting or attribution-only, and given a settlement relevance level based on when the change appeared relative to the record being final.
  6. Alert — anything detected writes an alert (JSON + Markdown) and, in the scheduled workflow, opens a GitHub issue so the change is reviewable without anyone watching a screen.
  7. Verify — nhl_monitor verify re-reads the official sources for a stored record so a record can never silently rot.

Two census methods for history

1. Frozen-era document vs current database

Official reports generated on game night are never regenerated in some eras (verified for 2005-06 and 2016-17). Those documents preserve the original ruling while the league's current API returns the current record, so any difference between them is a scoring change with both states coming from official artifacts.

2. Archived snapshots of the same document

The Wayback CDX index exposes a content digest per snapshot. More than one digest for an official document means that document changed; the distinct versions can then be diffed. This is the only method that works for the modern era, where documents are regenerated in place and the original bytes are gone.

What the classifier refuses to do

  • It never invents a reason. "Video review" is only recorded if an official artifact says so in words, because no machine-readable review feed was located (see Limitations).
  • It never treats a document regeneration as a scoring change. Regeneration is detected by the footer timestamp and excluded; only content differences create records.
  • It never counts a shootout attempt as a goal.
  • It never fills a gap. Missing fields are shown as gaps with flags.

Limitations — including what cannot be detected automatically

Open questions that need a human

  • Whether any specific sportsbook regraded a market after a correction — house rules are private and must be verified per operator.
  • Whether a correction was motivated by video review, a scorer's judgement call, or a league review — unless an official artifact states it.
  • Games where the only archive snapshot postdates the correction: the change is invisible to method 2 and must be resolved from the frozen-era method or from an official announcement.
