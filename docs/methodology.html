Methodology, Sources & Limitations

How records are built, what counts as evidence, how far back coverage can go, and what this project honestly cannot do. Read this before citing any record.

1. Mission (project prompt)

Build a complete, continuously updateable database of NHL scoring discrepancies and corrections using official NHL sources whenever available: the NHL Situation Room, official game reports, official scoring summaries, official team reports, and other trusted primary sources. Capture every identifiable event where the original scoring record/ruling was later changed — goals to no-goal, no-goals to goals, video-review reversals, scorer changes, assist changes, in-game, intermission, and postgame corrections. Preserve original and corrected state side by side, link the exact official source for every record, and flag anything incomplete, conflicting, or unverifiable instead of assuming.

Rules: unknown fields are null with a written flag — never guessed. Dates inferred from article context are marked inferred. Records are verified line by line; any irregularity is flagged for review rather than smoothed over.

5. Limitations (binding on this project)

  • No official corrections feed exists. Detection is snapshot-diffing (see Alert System), which finds state changes, not announcements.
  • APIs show corrected state only. Once the NHL updates a game, the pre-correction state is overwritten — forward monitoring must capture "before" snapshots itself.
  • X/Twitter monitoring is manual. @NHLPR posts are a primary source with no free monitoring API; collection is manual unless a compliant integration is added later.
  • Reasons need human sourcing. The API never explains why; every "reason" field must trace to a Situation Room/team/official text.
  • GitHub Pages + Actions constraints: static hosting only; scheduled checks run at cron granularity (minutes, not seconds); no true real-time push.
  • Human verification is mandatory before any monitored candidate enters the database. The monitor proposes; humans dispose.

6. Game-total market policy

Records distinguish goal-total changers (red) from attribution-only corrections (blue). A record is flagged possible total-market impact only when a goal was added or removed after the event initially appeared final (e.g. a review overturn after play stopped, or a postgame goal add/remove). Attribution-only changes never affect game totals, though they can affect player-point markets — that is noted per record, not asserted as settlement fact, because sportsbook correction/settlement rules differ.

7. Record schema

Canonical database file: docs/data/discrepancies.json (single source of truth for the site). Machine-readable schema: docs/data/schema.json. Validate with python scripts/validate.py. Required on every record: game date (or explicit unknown), teams, period/clock (or explicit unknown), initial ruling, corrected ruling, reason (or "not stated"), correction timing, video-review flag, goal-total vs. attribution flags, at least one source with URL, a verification tier, and a flags array.
