# Data model

Everything the site shows comes from committed JSON in `data/`. There is no database engine, no server and
no hidden state: if it is not in git, it does not exist.

## Files

| Path | Written by | Contents |
|---|---|---|
| `data/records/discrepancies.json` | `store.upsert_record` | the record store (append-only in spirit: revisions keep the superseded version) |
| `data/evidence/<game_id>/states.jsonl` | `store.append_evidence` | timestamped timeline of captured official states for that game |
| `data/games/<game_id>.json` | `store.save_game_state` | the latest captured state of the game, used as the diff baseline |
| `data/alerts/<ALERT-ID>.json` + `index.json` | `alerts.write_alerts` / `write_alert_index` | machine-readable alerts for the site |
| `data/exports/discrepancies.csv` | `cli export-csv` | flat export for spreadsheets |
| `data/reference/verified_facts.json` | hand-maintained, **append-only** | the anti-hallucination ledger: what was verified, when, from which URL |
| `data/reference/sources.json` | generated by `tools/build_site.py` | the source registry with verification status |
| `data/reference/bootstrap/…` | build-time | parser regression reference (labelled `state_kind = bootstrap_reference`, clearly NOT a live capture) |
| `data/schema/observed_vocabulary.json` | measured from the feed | every event type actually observed, so the classifier cannot claim unobserved events |
| `data/taxonomy.json` | hand-maintained | the vocabulary the site's filters are built from, including which values are not machine-detectable |

### Required vs requested

`store.REQUIRED_FIELDS` must be present or the record is rejected at write time (a record without a source
URL, without a period/clock or without an evidence status cannot be stored — the tests prove this).
`store.REQUESTED_FIELDS` is the charter's wish-list; anything missing is reported through `completeness()` and
shown on the site as a gap, never filled with an assumption.

### Enumerations

`data/taxonomy.json` is the single source of truth for the site's filter values and marks each one
`detectable` or `needs_human`. `classify.DISCREPANCY_TYPES`, `classify.TIMING_VALUES` and
`store.EVIDENCE_STATUSES` carry the definitions in code, and the unit tests pin the behaviour
(`goal_removed` ⇒ `affects_goal_total` ⇒ settlement level `high`/`critical`).

### Why `affects_goal_total` is computed from raw change types

The record-level names (`goal_to_no_goal`) and the change-level names (`goal_removed`) look similar, and on
2026-10-07 mixing them up silently disabled the entire settlement-impact logic. The unit tests now assert
both the classification and the flag, so the mistake cannot come back unnoticed.

## State fingerprints

`GameState.fingerprint()` hashes only the scoring record (state, team scores, and per goal: period type,
period, clock, team, scorer, assists, strength, own-goal) — not volatile fields such as retrieval time. Two
captures with the same fingerprint are the same record; a different fingerprint means the official record
moved, and the diff engine then says exactly how.

## Fields added by the announcement-ingest path (pass 3)

Records built by `ingest` carry the same required shape as auto-detected ones plus the fields below. The site
renders all of them in the record drawer.

| Field | Meaning |
|---|---|
| `case_id` | the case file in `data/inbox/statements/` this record is reproducible from |
| `status` | `auto_detected` or `verified_from_official_announcement` |
| `initial_state.evidence_status` | `verified_official` / `reported_by_secondary_source` / `official_artifact_residual` / `unavailable` — how the *pre-change* state is known |
| `corrected_state.evidence_status` | `verified` when an official report or feed shows the corrected credit |
| `change.declared_changes` | what the announcement says changed, as declared in the case file |
| `change.machine_diff` | the two declared states compared field by field: `same` / `changed` / **`indeterminate`** (a field neither state documents). A declared change that the states do not show, the two are compared and a flag says so |
| `timing.announced_at_utc` | the league announcement's own timestamp |
| `timing.game_ended_at_utc` + `game_end_time_note` | the documented end of the game and the conversion that produced it |
| `timing.latency_after_final_buzzer_seconds` | announcement minus end of game, computed only when both are documented |
| `sources[].role` | `corrected_state`, `official_announcement`, `official_announcement_reproduction`, `initial_state_corroboration`, `cross_check` |
| `sources[].document_generated_at` | the report footer, verbatim and unconverted |
| `sources[].quoted_row` | the exact report row the corrected state was read from (the "line by line" check, stored) |
| `sources[].retrievable_as_text` | false when the URL is cited but its text could not be read directly |
| `flags` | every missing or contradictory piece of evidence, named. Flagged is not the same as wrong: it means a named part of the evidence is absent |
