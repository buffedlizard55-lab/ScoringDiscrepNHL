Automatic Detection & Alert System

Continuously monitor official NHL feeds, snapshot scoring state, diff it over time, and raise an alert when something changes after it first appeared final. This page documents exactly what can and cannot be detected automatically.

Short answer: is it possible?

Yes — partially. There is no official NHL "scoring corrections feed", so the system detects discrepancies indirectly, by snapshotting official scoring state and diffing it:

  1. Poll the official NHL APIs on a schedule (scoreboard, play-by-play, boxscore).
  2. Snapshot every goal: period, clock, scorer, assists, score state.
  3. Diff each new snapshot against the previous one for the same game.
  4. Alert when a goal is added/removed or scorer/assist attribution changes — especially after the game reached FINAL.

This catches attribution corrections (the most common postgame change) and late goal add/remove events reliably. It cannot fully explain why a change happened — that still needs the Situation Room report or the @NHLPR post, which require human review.

What can be detected automatically

EventDetectable?How
Assist added / removed / swapped after the gameYesDiff boxscore/play-by-play goal details vs. earlier snapshot
Scorer changed to a different playerYesSame diff on scorer ID
Goal added to a FINAL game (late ruling correction)YesGoal-event count increased after final
Goal removed from a FINAL gameYesGoal-event count decreased after final
In-game review reversals (goal ↔ no-goal)MostlyRequires frequent live polling; fast reversals between polls can be missed
Score-state changes (period score edits)YesDiff scoreboard/boxscore linescore

What cannot be detected automatically (human review required)

LimitationWhy
Reason for the change (e.g. distinct kicking motion vs. goalie interference)The API shows the new state, not the explanation. Explanations live in Situation Room articles and @NHLPR posts.
Whether on-ice officials first ruled goal or no-goalAPI play-by-play typically reflects the final ruling; the intermediate announced call is often only in broadcasts/recaps.
Intermission vs. postgame timing of a correctionOnly known if polls bracket the moment; otherwise inferred from post timestamps.
@NHLPR scoring-change posts themselvesX/Twitter has no free official API for monitoring; posts must be collected manually or via third-party scrapers (fragile, ToS risk).
Situation Room article text at scaleNo structured feed; NHL.com news pages must be scraped and parsed (HTML changes break parsers).
Historical discrepancies (pre-monitoring era)APIs show current corrected state only — the original (pre-correction) state is gone. Backfill needs archived snapshots, RTSS reports, or contemporary reports.
Betting-settlement impactSettlement rules differ by sportsbook (e.g. stat corrections within 24h, goal-line vs. moneyline handling). The system flags potential impact only.

Latency

  • Live polls (GitHub Actions cron): detection delay ≈ poll interval (default 30 min in-season) + API update lag (seconds–minutes).
  • Postgame corrections (hours to days later): caught on the next scheduled re-check of recently-final games (default: re-check games from the last 3 days).
  • Very late corrections (days+): caught only if the lookback window still covers the game — the workflow re-checks a rolling window, not the whole season.

How alerts are delivered

  1. GitHub Issue (default): the scheduled workflow opens an issue titled [ALERT] Scoring change detected — … with before/after details. Watch the repo (Watch → Custom → Issues) to get email/push notifications.
  2. Workflow artifact: every run uploads alerts.json for audit.
  3. Database PR (human-in-the-loop): confirmed alerts are added to docs/data/discrepancies.json by a maintainer after verifying against an official source. The monitor never writes to the database by itself — this is deliberate, to keep the no-hallucination guarantee.

Run it yourself

# Check the last 3 days of games for scoring changes (needs internet)
python scripts/monitor.py --check-recent 3

# Snapshot one game
python scripts/monitor.py --game 2024020204

# Validate the monitor's diff logic without internet (fixture self-test)
python scripts/monitor.py --self-test

# Validate the database file
python scripts/validate.py

Source: scripts/monitor.py (standard library only — no dependencies) and .github/workflows/monitor.yml (scheduled runs + issue alerts).

Honest limits: this system detects state changes, not announcements. A correction it finds is a candidate discrepancy until a human confirms it against an official source and records both states with links. Anything the system cannot observe (reasons, intermediate on-ice calls, X posts) stays manual by design.
